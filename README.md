# DN Helper

Dragon Nest SEA 經典服（PC）小隊用的排隊工具。純靜態網頁，沒有後端，丟到 GitHub Pages 就能用。

## 三個頁面

| 頁面 | 檔案 | 做什麼 |
|---|---|---|
| 角色資料 | `roster.html` | 每個人填自己的角色、裝備（主武/副武/防具的裝等＋強化）、表攻/爆擊/防禦/終傷。也在這裡維護**職業庫** |
| 副本分團 | `raid.html` | 本週通關打勾表 ＋ 七個副本的分團表、外援補位建議、裝備缺口計算 |
| 深淵分隊 | `index.html` | 每日深淵的 4 人分隊（疲勞減免、帶/躺、吃水） |

三頁共用同一份名單，存在瀏覽器的 localStorage。

## 部署到 GitHub Pages

```bash
git init
git add .
git commit -m "DN Helper"
git branch -M main
git remote add origin git@github.com:<你的帳號>/<repo>.git
git push -u origin main
```

推上去之後到 repo 的 **Settings → Pages**，Source 選 `Deploy from a branch`、分支選 `main` / 根目錄，等一兩分鐘就會有網址。

> 一定要用 http(s) 網址開（GitHub Pages 或本機伺服器）。直接用 `file://` 雙擊開檔的話，
> 瀏覽器會擋掉載入 `data/roster.json` 的請求，「讀取 git 上的名單」那顆按鈕會失效（其他功能正常）。

本機要測就跑：

```bash
python -m http.server 8777
```

然後開 http://localhost:8777/roster.html

## 名單怎麼共用

localStorage 是各自電腦獨立的，所以用「匯出 JSON → commit」的方式同步：

1. 每個人開 `roster.html`，填好**自己**的角色和裝備
2. 按「只匯出這個人」，把那段 JSON 貼給團長
3. 團長按「合併貼上的人」（同名覆蓋、沒有的新增），五個人都合併完
4. 團長按「匯出全部」，內容存成 `data/roster.json`，commit + push
5. 其他人開頁面按「讀取 git 上的 data/roster.json」就同步到最新

## 職業庫要自己填

`roster.html` 下半部的**職業庫**是分團演算法的資料來源，預設是空的：

| 欄位 | 說明 |
|---|---|
| 屬性 | 火／水／光／暗。填了才會做「同屬性優先同團」 |
| 定位 | 輸出／補師／坦／輔助。用來判斷一團有沒有補、有沒有坦 |
| 隊伍 BUFF | 逗號分隔的標籤，建議用：增傷、爆擊、破防、減抗、回血、護盾、復活、解控、加速 |
| 增傷% | 這個職業給隊友的主要增傷數字，用來排誰跟誰一團比較賺 |

**沒填完的話**，分團只會照裝備戰力和人數排，不會做屬性分團、也不會給具體的外援職業建議
（頁面上會直接標出還有哪些職業沒填）。填完之後 8 人本那三個空位就會自動算出「這團缺補、缺破防 →
建議找 X、Y、Z」。

## 戰力怎麼算

```
戰力 = 表攻 × (1 + 終傷%) × (1 + 爆擊%)
```

終傷和爆擊要不要算進去可以在角色資料頁勾。爆擊欄請填**爆擊率 %**才適合算進去；
如果填的是未換算的爆擊值就把勾拿掉，它只會顯示不參與計算。

沒填表攻的角色，會用「裝等基準值＋強化權重」推估，再依照**已經填了表攻的角色**的平均比例
換算到同一個尺度，所以有填沒填的可以放在一起比。填的人越多推得越準。灰色數字就是推估值。

## 每週重置

打勾紀錄按「週期」存，預設每**週四**重置（可在角色資料頁改）。切到新週期時打勾表會自動變空白，
舊紀錄留在資料裡不會消失。
